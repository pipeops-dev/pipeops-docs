# Mintlify Migration Design

**Status:** Proposed
**Date:** 2026-08-28

## Goal

Migrate the PipeOps documentation site from Docusaurus to Mintlify as a clean cutover, while preserving the existing documentation content, assets, public URLs where practical, analytics, and a reusable archive of the current Docusaurus theme and color system.

## Context

The repository currently contains a Docusaurus 3 site with approximately 100 Markdown/MDX pages, an autogenerated sidebar, nested `_category_.json` metadata, custom React theme overrides, custom CSS, static assets, and PostHog/Google analytics configuration. The checked-out README already describes a Mintlify-style project, but the runtime configuration and dependency manifest are still Docusaurus-based. The migration must reconcile that inconsistency rather than layering a second documentation runtime on top.

## Decisions

### 1. Clean cutover

Mintlify will become the only supported documentation runtime in this repository. Docusaurus configuration, packages, theme swizzles, and Docusaurus-specific scripts will be removed from the active project. The existing content tree remains the source content set unless a page is explicitly identified as a Docusaurus demo or otherwise cannot be represented in Mintlify.

### 2. Mintlify source of truth

Create a root `docs.json` containing:

- site name, canonical URL, favicon, logo, and dark-first color configuration;
- Mintlify theme selection and navigation tabs/groups;
- links for PipeOps, GitHub, blog, community, and support destinations;
- analytics configuration for the existing Google Tag Manager/Google Analytics setup where Mintlify supports it;
- redirects from the legacy `/docs/...` routes to their Mintlify equivalents when paths change.

Navigation will be explicit and human-curated. It will preserve the meaningful Docusaurus hierarchy—getting started, projects, servers, add-ons, integrations, CLI, Kubernetes Agent, collaborations, how-to guides, troubleshooting, and changelogs—while excluding tutorial-demo material from the primary product navigation unless it is useful product documentation.

### 3. Content conversion

Convert content in place to Mintlify-compatible Markdown/MDX:

- retain valid YAML front matter and normalize titles/descriptions where needed;
- convert Docusaurus admonition syntax (`:::note`, `:::tip`, `:::warning`, `:::danger`, and variants) to Mintlify callouts;
- remove Docusaurus-only imports, `@theme` references, React page examples, and MDX constructs that require the Docusaurus runtime;
- preserve code fences, images, links, tables, and instructional content;
- move or rename files only when required for clean URLs or to remove spaces/underscores that are Docusaurus conventions;
- preserve legacy URLs with redirects whenever a path changes;
- treat files prefixed with `_` as intentionally excluded from primary navigation only when their Docusaurus behavior indicates draft/hidden support content; otherwise make the corresponding content reachable through explicit navigation or links.

The migration will not rewrite product prose wholesale. It will focus on syntax and metadata compatibility so the cutover remains reviewable and low risk.

### 4. Theme and branding archive

Mintlify’s built-in theme will be used live for the first migration. Before removing active Docusaurus theme code, archive the current system under `design-archive/docusaurus-theme/`, including:

- `src/css/custom.css`;
- `static/fonts/` and its stylesheet;
- active logo SVGs and relevant favicon assets;
- the Docusaurus navbar/footer/sidebar overrides and component source;
- a short `README.md` documenting the current palette (`#18181a`, `#1f1f21`, `#111111`, `#363538`, `#825dff`, `#a0a0a0`, `#d8d8d8`, and focus blue `#007acc`), Niveau Grotesk usage, logo references, and which styles are Docusaurus-specific.

The archive is reference material, not imported by Mintlify and not part of the deployed site unless Mintlify later gains a deliberate custom-theme integration.

### 5. Analytics and scripts

Keep analytics behavior that can be configured natively in Mintlify. The Docusaurus client module will not be carried over as-is because it depends on Docusaurus route lifecycle APIs. Any page-view tracking that Mintlify does not support natively will be documented as a follow-up rather than introducing an unsupported browser script during the base migration. The iframe compatibility script will be evaluated for actual content usage and retained only if it is still referenced by migrated pages.

### 6. Local development and verification

Replace Docusaurus scripts with Mintlify-compatible commands for local development and validation. Add a deterministic link/content check that can run without a deployed site. Verification must cover:

- dependency installation and local dev startup;
- Mintlify configuration parsing/build validation;
- all navigation targets resolving to existing pages;
- no broken internal Markdown links caused by renames;
- no remaining active Docusaurus imports, theme references, or admonition syntax;
- representative page rendering, including callouts, code blocks, images, nested navigation, and redirects.

## File impact

### Created

- `docs.json` — Mintlify configuration and navigation source of truth.
- `design-archive/docusaurus-theme/README.md` — archive index and palette notes.
- `design-archive/docusaurus-theme/custom.css` — preserved current custom CSS.
- `design-archive/docusaurus-theme/components/` — preserved custom React theme overrides.
- `design-archive/docusaurus-theme/assets/` — preserved font/logo references needed to reuse the current look.
- migration/link-check utilities and their tests, if the chosen Mintlify toolchain does not provide equivalent validation.

### Modified

- documentation pages containing Docusaurus-only syntax;
- `package.json` and lockfile for the Mintlify toolchain;
- `README.md` to document the real Mintlify workflow;
- `Dockerfile` if its command or runtime assumptions are Docusaurus-specific.

### Removed from active runtime

- `docusaurus.config.js`;
- `sidebars.js`;
- `babel.config.js` when no remaining active tool requires it;
- `src/` Docusaurus app/theme code after its reusable parts are archived;
- Docusaurus-only dependencies and scripts.

## Risks and mitigations

- **Mintlify feature mismatch:** keep conversion syntax conservative and validate representative pages locally before broad edits.
- **URL regressions:** generate a complete old-to-new path map and encode redirects in `docs.json`.
- **Hidden content loss:** inventory every page before editing; explicitly classify hidden/underscore files.
- **Analytics behavior change:** retain supported native integrations and document unsupported client-side behavior rather than silently claiming parity.
- **Branding loss:** archive exact source assets and palette values before removing the Docusaurus runtime.

## Acceptance criteria

1. The repository has one active docs runtime: Mintlify.
2. The complete intended product documentation set is reachable through Mintlify navigation or intentional links.
3. Existing public documentation URLs either remain stable or have explicit redirects.
4. The live configuration uses Mintlify’s theme and preserves PipeOps identity through logo, favicon, URL, links, and supported analytics settings.
5. The prior custom theme, fonts, logo references, colors, and relevant component code are stored under `design-archive/docusaurus-theme/`.
6. Local development and validation commands are documented and pass.
7. No active page depends on Docusaurus-only imports, theme APIs, or unconverted admonition syntax.
